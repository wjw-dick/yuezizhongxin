## ADR-001 采用模块化单体，不拆微服务

- **状态**：已接受
- **背景**：单租户日均订单数十单；多端共用业务逻辑；团队 6~8 人；运维只有一套 Docker Compose。
- **决策**：Spring Boot 3 模块化单体，按业务域拆 Maven 模块，模块间只通过服务接口与领域事件交互。
- **备选与取舍**：
  - 微服务 + 注册中心：可独立扩缩容，但运维与联调成本高、跨服务事务复杂；业务量不足以支撑，不选。
  - 单体不分模块：最快，但平台端与租户端边界模糊、后续拆分成本高；不选。
- **后果**：部署简单、事务一致；单模块压力突出时可独立拆出，模块边界已预留。
- **落地位置**：`pom.xml` 反应堆共 18 个模块；`docs/architecture.md` 第 4 节给出依赖方向；`common` 不依赖任何业务模块。

## ADR-002 多租户数据隔离采用共享库 + tenant_id

- **状态**：已接受
- **背景**：目标客户为区域连锁与单店；平台需跨租户统计开通率与用量；租户量短期不足 50。
- **决策**：单库共享表 + 全表 `tenant_id`；DAO 层拦截器统一注入条件；唯一约束一律带租户维度。
- **备选与取舍**：
  - 独立 schema：隔离更强，但连接池与 DDL 版本管理复杂，运维成本高；不选。
  - 独立库/实例：隔离最强但成本高、跨租户报表需汇总；只对大客户单独立项。
- **后果**：成本与运维最优；风险在漏加租户条件，靠「拦截器 + 代码扫描 + 越权回归」三重保障。
- **落地位置**：`common/web/MybatisPlusConfig`（TenantLineInnerInterceptor，上下文缺失时注入 `-1` 保证查不到数据）；`sql/*` 中 `uk_tenant_*` 复合唯一约束；`deploy/smoke-test.sh` 第 6 项越权用例。

## ADR-003 平台运营端与租户后台物理分离

- **状态**：已接受
- **背景**：平台方需管理租户、套餐与账单，但不得查看租户业务明细；租户管理员不得进入平台端。
- **决策**：两套路由（`/api/platform` 与 `/api/tenant`）、两套表（`platform_*` 与业务表）、两套角色、两个登录入口；账号表以「表」而不是「字段」区分。
- **备选与取舍**：单一后台按角色切换租户——开发省事，但权限边界模糊、越权风险高、审计难分离；不选。
- **后果**：前端维护两套壳；越权面收敛，验收必须覆盖「互相进不去」。
- **落地位置**：`platform_user` 与 `sys_user` 分表；`AuthInterceptor` 校验令牌 `platform` 标记与路径前缀，不匹配返回 40305；平台审计 `platform_audit` 与租户审计 `sys_audit_log` 分表落库。

## ADR-004 两个小程序共用一套组件层与请求层

- **状态**：已接受
- **背景**：用户端与护理师端同为微信原生小程序，订单、护理计划、房态等实体高度重叠。
- **决策**：同仓库多工程（`miniprogram-user`、`miniprogram-nurse`），共用 `components/`、`request/`、`utils/`、`constants/`（字典中文名常量），各端只保留页面与差异化样式。
- **备选与取舍**：
  - uni-app / Taro：一套代码多端，但订阅消息、扫码等原生能力适配与调优风险高；只需两个微信小程序，不选。
  - 两端各写一套：互不影响，但字典与请求层重复、BUG 双改；不选。
- **后果**：字典与接口改动一次生效；提审需按端分别进行。
- **落地位置**：阶段 9/10（T71、T79）按此结构创建；字典常量以 `sys_dict_item.item_name` 为准，前端不得硬编码英文编码。

## ADR-005 RabbitMQ 承担异步通知与延迟任务

- **状态**：已接受
- **背景**：入住提醒、尾款催缴、42 天回访、护理异常通知、模板消息推送均有时序要求，且不能阻塞下单与记录主链路。
- **决策**：引入 RabbitMQ，延迟队列（TTL + 死信转发）承载定时提醒；消息体统一携带 `tenant_id`；消费失败重试 3 次后入死信并告警。
- **备选与取舍**：
  - 仅数据库轮询：无额外组件，但精度差、大表扫描压力大；不选。
  - Kafka：吞吐高，但延迟队列实现复杂、运维重；当前量级不需要，不选。
- **后果**：需新增队列监控与死信告警；定时任务按租户分片投递。
- **落地位置**：`deploy/docker-compose.dev.yml` 已含 rabbitmq（vhost `/yuezizhongxin`）；队列声明与消费者在 T37/T40/T49 落地，消息体统一为 `{tenantId, tenantCode, payload}`。
